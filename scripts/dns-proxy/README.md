# dns-proxy для 3x-ui-pro — v0.2.2

Интерактивный патч Linux-сервера с 3x-ui. Выбирает DNS-Proxy, показывает план и предупреждения, сохраняет точечный откат, применяет настройки и автоматически активирует их перезапуском x-ui. В конце предлагает проверить сайты и при необходимости откатить изменения.

Проверено: 3x-ui 3.8.5 / Xray 26.9.9; синтетические сценарии в памяти и dry-run на двух серверах. Эта версия интерактивного установщика ещё не прошла реальную установку с GitHub. Самостоятельное применение через SSH первоначальной версии было проверено на первом сервере с клиентской DNS-диагностикой.

## Запуск с GitHub в две команды

Замените OWNER/REPO вашим репозиторием. Команды выполняются **на целевом Linux-сервере**, в обычном SSH-терминале:

```bash
curl -fL https://raw.githubusercontent.com/OWNER/REPO/v0.2.2/install.sh -o dns-proxy-install.sh
sudo bash dns-proxy-install.sh --repo OWNER/REPO --ref v0.2.2
```

Если уже работаете как root, sudo можно убрать. Используйте проверенный тег релиза или полный commit SHA, а не изменяемый main. Загрузчик проверяет SHA256SUMS и сохраняет исполняемый код для последующего отката. Не устанавливает пакеты. Открытый терминал нужен для меню и проверки сайтов; чтение ответов поддерживается через /dev/tty.

Инструкция публикации: [PUBLISH.md](PUBLISH.md).

## Первое меню: выбор DNS-Proxy

```text
Какой DNS-Proxy использовать для Gemini?
1 — GeoHide: https://geohide.ru/dns-query
2 — BezMezhau: https://dns.bezmezhau.com/dns-query
3 — Comss.one: https://dns.comss.one/dns-query
4 — XBox DNS: https://xbox-dns.ru/dns-query
5 — dns.malw.link: https://dns.malw.link/dns-query
6 — Свой DNS-Proxy
```

Затем выбирается протокол:

- **DoH, рекомендуется:** полный URL из раздела DNS-over-HTTPS провайдера, с https:// и полным путём. Например `https://dns.bezmezhau.com/dns-query`. Не URL главной страницы и не имя из раздела Android Private DNS / DoT.
- **Обычный DNS:** один основной IPv4 из раздела IPv4 DNS / Primary. Например `143.20.64.55`. Без https://, порта и запятых. Это DNS-over-UDP на порту 53.

При DoH несколько IP провайдера вводить не нужно: используется имя из полного URL. При обычном DNS установщик использует только основной IPv4; дополнительный показывается для справки и автоматически не используется. Если основной недоступен, можно повторить установку со своим дополнительным IPv4. Не вводите IP прокси из hosts-файла или IP, который провайдер вернул на запрос Gemini: это не обязательно адрес DNS-резолвера.

Список и источники адресов находятся в [providers.json](providers.json). Адреса сверены 09.10.2026. GeoHide DoH проверен на первом сервере; его IPv4 из этого каталога предоставлены пользователем и отдельно не проверены. У остальных провайдеров публикация адреса не означает, что Gemini обязательно заработает именно на вашем сервере. Обычные Cloudflare/Google DNS не заменяют проксирующий DNS.

## План и предупреждения

До записи в БД установщик показывает выбранные inbound, изменения и последствия. При предупреждениях можно продолжить либо отменить. Продолжение подтверждается выбором «1»; по умолчанию — отмена.

Обрабатываемые предупреждения:

- Несколько правил DNS для google-gemini: объединяются в одно.
- Gemini и другие домены в одном правиле: Gemini выделяется отдельно, остальные домены сохраняют прежний DNS.
- Прочие scoped DNS-правила: сохраняются, но могут пересекаться с Gemini.
- Активный маршрут Google/Gemini к другому прокси: предупреждение с доменами и outbound; маршрут сохраняется, поэтому Gemini может продолжить идти через него даже после успешной установки.
- Нет тега direct, но есть единственный freedom: выбирается этот freedom без переименования.
- Первый/default outbound не freedom: предупреждение, порядок outbound сохраняется.

Технически небезопасные ситуации остаются ошибками, которые нельзя проигнорировать: несовместимая БД/версия Xray, нет GeoSite, неизвестный или неоднозначный freedom, не-freedom под ожидаемым direct-тегом, повреждённый JSON, пользовательские триггеры, DNS URL с паролем, глобальное использование выбранного Proxy DNS в виде строки, индивидуальные IP-фильтры единственного Gemini DNS, изменения конфигурации во время применения. Установщик не заменяет неизвестные настройки произвольно.

Предусловие: Gemini → WARP заранее отключён или отсутствует. Патч не управляет этим правилом и не делает его наличие причиной отказа. Если оно всё-таки активно, Gemini может продолжать идти через WARP.

## Что изменяется

- Sniffing активных локальных поддерживаемых inbound: enabled=true, HTTP и TLS добавляются к существующим destOverride. QUIC/FakeDNS сохраняются. Присутствующие metadataOnly/routeOnly становятся false; отсутствующие поля уже имеют false по умолчанию.
- DNS-сервер только для geosite:google-gemini: выбранный адрес, skipFallback=true, finalQuery=true, queryStrategy=UseIPv4, disableCache=true, timeoutMs=4000.
- Общие DNS queryStrategy=UseIPv4 и disableFallbackIfMatch=true; routing.domainStrategy=IPIfNonMatch; freedom settings.domainStrategy=UseIPv4.
- Существующие обычные DNS сохраняются. Если servers пуст, обычные DNS берутся из config.json.

UUID, пользователи, настройки клиентов, stream_settings, REALITY-ключи, сертификаты, порты, существующие маршруты и остальные outbound не обновляются. Повторный запуск не создаёт DNS-дубли. Без изменений нет новой записи отката и нет перезапуска.

Число, имена и порты inbound не фиксированы. Поддерживаются VLESS, VMess, Trojan, Shadowsocks, SOCKS, HTTP, mixed с tcp/raw, ws, xhttp, grpc, httpupgrade, http/h2, kcp, quic. API/tunnel, выключенные, удалённые node-inbound и неподдерживаемые протоколы пропускаются. Hysteria/Hysteria2 исключены из изменений sniffing.

DNS/direct общие для Xray: они могут менять поведение Hysteria и других исключённых inbound. Наличие Hysteria установку не блокирует. Перезапуск x-ui может кратко прервать все подключения, включая Hysteria.

## Применение, активация, проверка сайтов

Подтвердив план, пользователь разрешает запись изменяемых полей, создание записи отката и перезапуск сервиса. Установщик работает одной SQLite-транзакцией, повторно сверяет план и не затирает конкурентные изменения. Затем перезапускает x-ui, проверяет active и появление процесса Xray.

При обнаруженной ошибке активации выполняется попытка точечного отката и повторного запуска. Если настройки после применения изменились, откат отказывается их затирать и потребуется ручная диагностика. Успешная проверка процесса не гарантирует успешный доступ к сайтам.

Последнее меню:

```text
Проверьте Gemini, Gmail, YouTube и GitHub через каждый нужный inbound.
1 — Всё работает, завершить
2 — Сайты не работают: откатить изменения и перезапустить сервис
3 — Проверю позже: оставить настройки и сохранить команду отката
```

При выборе 2 возвращаются только поля этого применения и автоматически активируется возврат. При выборе 3, закрытии последнего меню или Ctrl+C на этом шаге настройки остаются; запись отката и её команда сохранены. Внезапный обрыв раньше этого шага тоже требует проверки состояния и, при необходимости, ручного отката.

## Запись отката и последующий возврат

Запись создаётся в `/etc/x-ui/dns-proxy-state/` с правами каталога 0700 и файла 0600. Содержит изменяемые DNS/IPv4/sniffing поля и связанные проверки; не содержит UUID, клиентские настройки, REALITY-ключи или приватные сертификаты. DNS и маршруты могут содержать частные домены, поэтому файл не публикуется.

Это **не полный бэкап** и не защита от повреждения всей БД/диска. Полный бэкап сервера отложен в рамках этой задачи. State-файл применим только к своей БД; не переносите чужую БД/state на другой сервер.

Код, загруженный с GitHub, сохраняется в `/usr/local/lib/dns-proxy/<SHA256-манифеста>/`. После применения программа печатает точную команду возврата, например:

```bash
sudo python3 /usr/local/lib/dns-proxy/HASH/dns_proxy.py rollback --restart --state /etc/x-ui/dns-proxy-state/FILE.json
```

Здесь HASH и FILE заменяются реальными значениями из вывода установщика. Откат не затрагивает изменения пользователей и трафика, которые произошли после установки. Если изменены именно поля патча или связанные маршруты, автоматический откат отказывается затирать их. Несколько применений откатываются в обратном порядке.

## Дополнительные команды

Локально, из каталога патча:

```bash
python3 dns_proxy.py dry-run
python3 dns_proxy.py dry-run --dns https://dns.bezmezhau.com/dns-query
python3 dns_proxy.py dry-run --dns 143.20.64.55
python3 dns_proxy.py install
python3 dns_proxy.py verify --dns https://geohide.ru/dns-query
python3 test_memory.py
```

Для выборочного запуска: `--ids 2,4` либо `--tags TAG1,TAG2`. Для нестандартных путей: `--db`, `--xray`, `--geosite`, `--config`. Ожидаемый freedom-тег задаётся direct_tag в config.json. Для другого сервиса можно использовать --service, если он запускает Xray как дочерний процесс.

Для низкоуровневого apply нужно явно указать --state, создать закрытый каталог заранее и при наличии предупреждений добавить --accept-warnings. apply/rollback перезапускают сервис только с --restart. Предпочтительный режим для пользователя — install.

Важно: verify использует адрес из config.json, если --dns не указан. После выбора другого провайдера передавайте verify тот же --dns. Install проверяет именно выбранный адрес и не перезаписывает общий config.json.

Сам Python dry-run читает БД в read-only режиме и проверяет GeoSite/Xray без записи тестовых конфигов. Bash-загрузчик даже для dry-run скачивает и сохраняет файлы программы, но не изменяет настройки панели и не перезапускает сервисы:

```bash
sudo bash dns-proxy-install.sh --repo OWNER/REPO --ref v0.2.2 -- dry-run
```

## Требования и границы проверки

Linux, Python 3.9+, SQLite с JSON-функциями, совместимая локальная структура 3x-ui (включая node_id), systemd, Xray >=26.9.9, непустой google-gemini в указанном GeoSite. Загрузчик требует curl, sha256sum, bash и обычные системные утилиты. Пакеты автоматически не устанавливаются.

Xray -test использует минимальную конфигурацию через /dev/stdin, без чтения производственных ключей. Это проверка необходимых параметров, а не полного рабочего конфига и не клиентского DNS-пути. GeoSite и Xray не обновляются. IPv6 DNS-серверы, DoT, DoQ и адреса с авторизацией в этой версии не поддерживаются.

Состав google-gemini зависит от GeoSite и может включать другие Google AI-сервисы. Патч не включает подробное логирование. Для фактической DNS-проверки согласуйте временные DNS-логи отдельно; они могут сохранять домены других пользователей.

SHA256SUMS проверяет согласованность загруженных файлов. Если злоумышленник контролирует сам репозиторий, он может заменить и код, и манифест. Поэтому источник и закреплённый релиз должны быть доверенными.

## Название проекта и прежние установки

Проект называется dns-proxy. Gemini остаётся набором доменов по умолчанию; geosite:google-gemini — имя группы GeoSite, его не переименовывают. После установки список доменов можно менять в DNS-правиле панели с учётом поддержки сайтов провайдером. Повторное применение патча по-прежнему настраивает группу из config.json.

Новый скрипт dns_proxy.py принимает прежний формат записей отката gemini-dns-patch-v1. Существующие записи не переносите: укажите их исходный путь через --state. При откате сохраняются проверки изменений после установки.

Версия 0.2.2: после перезапуска установщик проверяет запуск Xray до 30 секунд, обновляя PID панели при каждой проверке.
